# 个人设备自动接续

首次配对后，Git 项目按 GitHub 的 `owner/repo` 同步代码。桌面端没有项目时，澜汐从 GitHub 克隆一份。普通项目按各机母目录下的相对路径对应，保留原来的会话 ID。两端可以选不同盘符。

| 同一项目的文件 | 笔记本 | 台式机 |
|---|---|---|
| 代码 | `D:\Work\客户甲\A\src\main.py` | `E:\Projects\客户甲\A\src\main.py` |
| 默认项目记忆 | `D:\Work\客户甲\A\.codex\memories\decision.md` | `E:\Projects\客户甲\A\.codex\memories\decision.md` |
| 设置项目记忆目录为 `notes/Codex` | `D:\Work\客户甲\A\notes\Codex\decision.md` | `E:\Projects\客户甲\A\notes\Codex\decision.md` |

## 在各台电脑设置项目母目录

在各台电脑上打开同一私人版并选「连接云服务器」。各机需要有对应的 GitHub 仓库权限和可用的 Git 提交身份。首次使用时，各台电脑分别选择本机的项目母目录。 [安装与连接](PORTABLE_CHECK.md)

例如 `D:\Dev\VSCode` 和 `D:\Dev\PyCharm` 都放项目，可以把 `D:\Dev` 设为项目母目录。项目 A 在一台电脑的 `VSCode\A` 里、在另一台的 `PyCharm\A` 里时，只要两份已存在的仓库都能被扫描到且 Git `origin` 指向同一个 GitHub 仓库，澜汐会复用各自的目录。接收端尚无该仓库时，澜汐沿用来源机的相对路径克隆。想把它放在不同位置，可以先在目标目录克隆，再让澜汐扫描该目录。

平时只需让澜汐在托盘运行。后台最多并行检查四个仓库，每轮完成后默认等待 10 秒。编辑器保存、GitHub 网页提交或任一设备推送后，其他在线设备会在后续检查收到改动。休眠、断网、Git 身份不可用时，恢复后自动重试。代码经 GitHub 传输，个人通道传递项目清单和记忆。只要本机已有项目清单，个人通道短暂离线时仍可同步代码。

仅需同步已在各机登记的仓库时，可以选择「仅启用已登记项目的 GitHub 同步」。自动发现新项目、全局规则和会话续接需要完成个人通道配对。

## 项目分组与同步优先级

在主窗口顶部选择「任务 → 项目分组与同步…」。可添加、重命名或删除「工作」「娱乐」「科研」等分组，把项目移入分组，并为每个项目选择「高优先级」「每 12 小时」「每 24 小时」或「进入后同步」。这些设置保存在当前电脑。高优先级项目先进入自动同步队列。12 和 24 小时从最近一次成功同步算起。

本机已有项目时，澜汐先显示本地会话，点击「启卷」可直接打开 VS Code。进入约 5 秒后安排后台同步。同一项目的连续点击合并为一次请求，遇短暂断网会在应用运行时重试。项目尚未下载时，澜汐继续从服务器准备本地目录。手动「合流」和跨机交还可立即安排所需同步。

## 手动同步

R38 支持来源机的普通项目。澜汐发现有 Codex 会话或受支持项目标志的目录后，在已连接个人云同步的来源机初始化 Git，提交符合自动同步规则的源码，使用该机 GitHub 登录账号创建同名私有仓库并推送。需要 Git for Windows，以及有权建私有仓库的 GitHub CLI 或 Git 凭据管理器登录。GitHub 登录不可用时保留本地首提交，稍后重试。同名远程归属不明时在「合流」中提示人工核对。首次接入和后续自动提交均过滤常见凭据、缓存、构建目录和达到 100 MiB 的文件。

例如原机选择 `C:\Users\gjh` 为母目录后，点「合流」，查看 `vscodePronject\Satisfactry` 的项目映射和 Git 接入结果。接收机升级后连接同一私人工作区，点「合流」并在「案头诸事」打开自己母目录下同一相对路径的会话。接收机可以先收到会话，等来源机的私有仓库就绪后再取得代码；同名或名称相近的临时检出各自独立。母目录自身、系统临时目录及接收端的会话占位目录不自动建库。

排查“项目只有启卷”时，可在两台 Windows 电脑分别双击[诊断项目会话.cmd](../scripts/诊断项目会话.cmd)。脚本默认检查本次排查的 `vscodePronject\Satisfactry` 和 `AppData\Local\Temp\satisfactory-sbp-source`，也支持把实际项目文件夹拖到脚本上。报告列出本机项目路径、GitHub 仓库名、接续索引中的线程 ID，以及匹配的本机会话文件大小。用仓库名和线程 ID 对照两机结果。文本报告保存在窗口末尾显示的临时目录，只含诊断元数据。

鼠标移到主窗口顶边，点「合流」。R40 会显示正在执行的一轮同步，窗口列出当前阶段、已用时间、已处理仓库数和正在检查的仓库。后台空闲时会立即安排一轮。GitHub HTTP 请求长时间没有数据时会显示超时，其他仓库继续处理。结果列出代码同步状态、记忆检查以及本机缺少或大小不同的大文件。代码经 GitHub 更新，记忆和大文件清单经澜汐协调服务刷新。大文件本体可按需借用。 [文件操作](PORTABLE_CHECK.md#跨机借用与回传大文件)

R35 的结果会逐项列出 GitHub 仓库、本机路径和状态，包括已同步的项目。项目映射无效时，其他项目仍可继续同步。只使用本机功能时，案头仍读取当前 Windows 用户的 Codex 会话。要在另一台电脑上看到笔记本的会话，需要在笔记本连接同一云工作区，等对应项目和完整会话轮次同步完成。

代码和会话使用不同连接。连接澜汐云服务器后，GitHub 私有仓库仍需要当前 Windows 用户具备仓库权限，并通过本机 Git 凭据助手登录。可在对应项目目录执行 `git ls-remote --symref origin HEAD` 核对读取权限。

R39 的「合流」遇到 Git 拒绝访问本机仓库时，显示「信任 Git 目录并重试」。选择你确认可信的仓库目录并确定，澜汐将该目录加入当前 Windows 用户的 Git `safe.directory`，并立即安排下一轮合流。设置在该电脑的当前账号下生效。GitHub 凭据、检出或网络失败继续按对应提示处理。

## 代码的服务器备份

R35 在同一轮检查 GitHub 同步和服务器代码备份。这两项分别显示结果。

- **自动同步**。选择「连接云服务器」并保持澜汐在托盘运行。已登记的本机项目文件发生变化后，后台上传新的备份。内容未变时复用服务器已经确认的副本。
- **手动同步**。点顶部「合流」，立即安排一轮检查。逐项核对 GitHub 与服务器备份结果。GitHub 登录失败时，服务器仍可保存当前工作区中已落盘、符合备份条件的文件。
- **下载**。在顶栏「澜汐」或托盘打开「跨机接续 → 下载服务器代码备份」，填写 `所有者/项目` 并选择来源设备与备份时间，保存 ZIP。可在 GitHub 不可用时使用；下载的 ZIP 独立保存，需要时自行解压。

每个项目、每台设备在私人工作区保留最近一次成功校验的 ZIP，上传未完成时保留上一份。备份包括符合自动同步规则的本机已跟踪文件和新源码。忽略的新文件、常见凭据、项目记忆目录、Git 过滤器管理的文件、目录链接、100 MiB 及以上文件，以及未落盘的编辑缓冲区留在本机。ZIP 提供工作区文件快照。GitHub 继续管理提交历史和分支。单个服务器 ZIP 上限为 1 GiB。

## 使用现有澜汐协调服务

两台电脑可通过同一个 HTTPS 地址接续。在阿里云或其他 Linux 服务器上可使用仓库里的 Compose 配置和设备登记工具部署。 [澜汐云协调服务](CLOUD_COORDINATOR.md)

按[项目控制说明](PROJECT_CONTROL.md)启动协调服务。在服务端的设备登记中，为同一人的两台设备填写相同的 `personalSpace` 和各自独立的随机 `token`。每个令牌至少 32 字节。只有登记在该个人空间的设备可以读写其项目清单、记忆和会话。服务端示例中的令牌需替换。

```json
{
  "laptop": {"token": "<笔记本设备令牌>", "projects": [], "personalSpace": "my-devices"},
  "desktop": {"token": "<台式机设备令牌>", "projects": [], "personalSpace": "my-devices"}
}
```

客户端 `local-config.json` 中合并以下内容，并在各台电脑设置环境变量 `LANXI_DEVICE_TOKEN`。台式机使用自己的设备名与令牌。跨机服务使用 HTTPS。纯个人接续允许 `projects` 为空。

```json
{
  "coordination": {
    "url": "https://lanxi.example",
    "device": "laptop",
    "projects": {}
  },
  "personalSync": {}
}
```

## 项目目录与分支

从托盘选择配对方式后，R21 将设置保存到 `%LOCALAPPDATA%\Lanxi\data\personal-sync.json`，可从托盘打开该数据目录。也可以在 `local-config.json` 的 `personalSync` 中提供设置，托盘保存的同名键优先。在来源设备上可登记项目已有的记忆相对路径，接收机自动采用。以下是来源机 `personal-sync.json` 示例。

```json
{
  "exchange": "\\\\fileserver\\private-lanxi",
  "checkoutRoot": "D:\\LanxiProjects",
  "projects": [
    {
      "remote": "https://github.com/owner/a.git",
      "path": "D:\\Work\\A",
      "branch": "main",
      "memoryPath": "notes/Codex"
    }
  ]
}
```

`checkoutRoot`、`path` 是各机自己的绝对路径。`memoryPath` 使用项目根目录下的相对路径，各层用 `/` 分隔。默认值为 `.codex/memories`。修改已配对项目的相对目录后，其他设备从共享记录恢复到新位置；迁移前的本地文件保留。GitHub 默认分支用于首次克隆，指定 `branch` 时跟随该分支。用户暂时切到其他分支时，后台等待该工作区返回登记分支。

## 保存、更新与大文件

后台常规同步只发布已跟踪或手工登记的大文件清单。接收端在托盘「跨机接续」查看本机缺少、大小不同的文件及上次清点设备。大小相同的文件在清单中视为一致。R28 的按需借用会临时传输所选文件，回传时核对完整 SHA-256。完成后服务器清理临时文件。 [借用与回传](PORTABLE_CHECK.md)

- 后台把符合条件的已保存修改和新源码合成普通 `WIP` 提交，推送到登记分支。删除和重命名也会反映在接收端。工作区包含人工暂存、变基或未解决的 Git 操作时会显示等待，结束后自动重试。编辑器尚未保存的缓冲区留在编辑器中。
- 两端修改不同位置时，能够干净合并的提交自动合并。同一处冲突会保留本地和远端提交，托盘显示冲突。用户解决后后台继续推送。工作区属于别的仓库、克隆位置已有其他文件或已有用户自行设置的稀疏检出时，后台保留原目录并显示原因。
- 新克隆使用 Git 的部分克隆和稀疏检出。大文件的边界为单文件 **100 MiB 及以上**。普通 Git 大对象留在远端，LFS 文件只接收小指针。已有仓库中的大文件保留在本机；远端要替换本机已有的大文件时等待处理。历史里已手工提交超限对象时，自动推送暂停。远端必须声明支持 Git 对象过滤。此次验证使用 Git for Windows 2.56.0 和 Git LFS 3.8.1。 [Git 部分克隆](https://git-scm.com/docs/git-clone) · [稀疏检出](https://git-scm.com/docs/git-sparse-checkout)
- 遵守 Git 忽略规则，自动提交通道还跳过私有配置、常见凭据文件、Git 过滤器处理的文件和项目记忆目录。记忆目录同时写入本机 `.git/info/exclude`。已经手动纳入 Git 历史的文件仍受该仓库的访问权限约束。

## Codex 记忆与会话

| 内容 | 接收端落点 |
|---|---|
| 项目记忆笔记 | `<项目>/<memoryPath>/` 下的原相对路径 |
| 原生长期记忆 | `<项目>/<memoryPath>/.lanxi/long-term/<线程ID>.json`，本机存在兼容的 `memories_1.sqlite` 时按线程导入 |
| 可续接的完整轮次 | `<项目>/<memoryPath>/.lanxi/sessions/<原文件名>`，同时安装到本机 `CODEX_HOME/sessions` 供原生 Codex 续写 |
| 全局规则与长期笔记 | 本机 `CODEX_HOME/AGENTS.md` 和 `CODEX_HOME/memories/`，未设置该变量时使用用户目录中的 `.codex` |

支持 Markdown、纯文本、JSON、JSONL、YAML 和 TOML 记忆笔记。单条笔记记录仍需小于 10 MiB。两台设备同时修改同一记忆会保留双方版本并在托盘提示。R38 对已完整落盘的长会话使用 4 MiB 分块和 SHA-256 校验，可在中断后重试，支持最大 64 MiB 的原生会话文件。小会话继续兼容原记录。两台电脑都升级后可接续长会话；原生写入锁被占用时等待重试，历史分叉时保留双方。澜汐使用原线程 ID，将工作目录映射到当前电脑的项目目录。桌面可直接选择该会话。已安装 PowerShell 终端适配器的开发机在相应目录输入 `codex` 会选择最近已准备的会话。 [终端适配器](PROJECT_CONTROL.md)

个人通道包含可读的原生对话内容。共享目录 ACL 或协调服务器存储应只向本人授权。个人同步读取选定的笔记、长期记忆字段和已完成会话。登录凭据、整份 SQLite、WAL 及运行中的进程均留在原设备。复验环境及未做的物理机验收见[实施与验收记录](archive/IMPLEMENTATION_LOG.md)。
互动式项目占用与交还见 [跨设备项目控制](PROJECT_CONTROL.md#个人版项目占用)。吉光片羽中的随记、待办、完成状态、归档和手动分组按条同步到已配对设备。两端同时编辑同一字段会出现「冲突副本」，可在吉光片羽中查看。

支持「每日记录」的版本也会同步跨天保留的旧正文和待办状态。两台设备用已同步的条目各自按本机日期生成列表，原有逐条同步协议继续兼容旧版。 [每日记录入口](DESKTOP.md#吉光片羽)
