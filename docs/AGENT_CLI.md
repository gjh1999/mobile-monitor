# 轻量级 Agent 调度 CLI（需求草案）

状态：交互、角色、工单、可见性、报告、日志、Rust 核心、项目隔离、自动审批、目标模式和 token 记录已确认；具体接口、模型标识、策略默认值与验收方案待定。尚未开发、验收或发布。本文记录 2026-11-28 的需求讨论，不代表现版澜汐已有此入口。

[项目主文档](跨设备开发工作台方案.html#agent-cli) · [调度 CLI 架构](AGENT_CLI_ARCHITECTURE.md) · [开发计划](AGENT_CLI_PLAN.md) · [当前架构](ARCHITECTURE.md)

## 已确认的方向

- 以 CLI 与用户交互，由澜汐提供轻量级调度中枢。
- Codex 主控负责理解需求、拆分任务、分发、汇总，并复核一般任务。
- DeepSeek Flash 承接常规执行任务。
- Codex Astra 承接高难度任务及重点复核。这里沿用讨论中的名称，实际可用模型标识待核对。
- 核心后端使用 Rust。以项目为调度、权限、代码、工单、日志和用量归集的边界；项目之间的代码执行环境与写入范围隔离。
- 支持目标模式：用户设定目标，主控持续规划、推进、检查和报告，用户可查看、暂停、恢复或结束目标。目标完成条件及预算上限可配置。
- 支持自动审批，但只能命中项目内显式配置的规则。每次审批写入工单；未命中规则或缺少完整详情的请求等待人工处理。

## CLI 交互和透明度（已确认）

- 用户可以与中枢持续对话，追问进度、修改目标和介入决策；Agent 之间也可以交流。
- **每个动作和 Agent 间每次交流都通过项目工单完成。** 派工、消息、执行请求、工具调用、审批、复核、返工、结果和异常都关联工单及事件 ID。用户对话中导致动作的指令也要关联工单。
- 终端直观显示项目、目标、工单列表、各 Agent 的状态、当前负责的任务、进度、待审批和额度限制。进度来自可核对的工单事件和验收项，不把模型自行声称的百分比当作事实。
- 每个 Agent 可单独设置模型标识、接入方式、思考强度或等效参数、权限、并发与预算等其实际支持的选项；不支持的选项明确标示，不伪装生效。设置可查看、修改和恢复，变更记录归属项目及操作者。
- 定时报告项目与目标进展、已完成和阻塞的工单、各 Agent 状态及用量。遇到审批请求或额度限制立即报告，说明影响范围、等待原因和可采取的操作。报告频率、渠道和免打扰策略待确定。
- 保存可检索的持久日志，至少能按项目、目标、工单、Agent 和时间查找动作、消息、审批、状态变化、错误与报告；密钥及敏感原文需要脱敏，保留期限可配置。
- 记录每次模型调用的输入、输出、缓存及总 token（以接口实际返回字段为准），并汇总到 Agent、工单、目标和项目。缺少用量字段时显示“未知”及来源，不补造精确数值；重复事件和重连补传不能重复计数。

## 建议的最小流程（待确认）

1. 用户在项目目录启动 CLI，选择项目并输入目标。主控先读取该项目规则与文档，建立目标工单、子工单和可检查的验收条件。
2. 主控按任务复杂度在工单中派发。执行者只取得该项目的明确目录、任务说明、产物路径和权限；项目进程、工作目录与文件写入范围由 Rust 核心校验。
3. 执行者在工单中回传消息、完成状态、文件差异、验证命令及结果。主控检查差异与结果；高难度或争议项再交 Astra 复核。
4. 检查未通过时，主控在工单中给出具体返工意见并限制重试次数。通过后向用户报告改动、验证、token 用量与剩余问题。

首版建议串行派工，工单状态至少包括待派发、执行中、待复核、需返工、待审批、额度受限、已完成和失败。工单事件、状态、报告、调用用量与每次派工回执应持久保存，以便 CLI 中断后恢复；送达结果不确定的动作先核对，不盲目重复执行。并行写同一工作区、自动合并与自动发布先不纳入最小范围。

## 建议的首版终端布局（待确认）

```text
项目 / 目标                 工单与进度                 Agent 状态
当前项目 / 当前目标        #12 执行中  2/4 验收项      Codex 主控  复核中
输入与主控对话             #13 待审批                  DeepSeek Flash  空闲
工单消息与动作时间线       #14 额度受限                Codex Astra  空闲
底栏：待处理审批 · 下次报告时间 · 各 Agent/项目 token 用量
```

工单时间线应能展开查看 Agent 间原始交流、动作请求和回执。定时报告只是摘要，完整依据仍在工单与日志中。

## 需进一步确定

- “DeepSeek Flash”和“Codex Astra”的准确服务、模型标识及接入凭据方式。
- 执行端是 API、现有 CLI，还是二者都支持；对模型的工具调用、文件写入与命令运行开放到什么程度。
- 主控判断高难度、升级复核、失败重试和请求人工决策的规则。
- 自动审批规则的表达方式、默认关闭还是启用、允许的工具/命令范围和失效条件。
- 目标模式与现有 Codex 原生 goal 的关系，以及目标完成判断和预算耗尽行为。
- CLI 命令名称、终端交互细节、报告频率、费用与用量上限、日志保留期限，以及首版验收用例。

现版 `universal_rpc.py` 已连接 Codex App Server，桌面后台有任务控制、审批与持久化能力；这些只能作为设计参考，尚未构成上述多模型调度 CLI。开发前须核对新入口与现有桌面控制权、审批和工作区规则的一致性。
