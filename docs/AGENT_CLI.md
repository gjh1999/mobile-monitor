# 轻量级 Agent 调度 CLI（需求草案）

状态：交互形式和角色方向已确认；接口、模型标识、执行权限与验收标准待定。尚未开发、验收或发布。本文记录 2026-11-28 的需求讨论，不代表现版澜汐已有此入口。

[项目主文档](跨设备开发工作台方案.html#agent-cli) · [当前架构](ARCHITECTURE.md)

## 已确认的方向

- 以 CLI 与用户交互，由澜汐提供轻量级调度中枢。
- Codex 主控负责理解需求、拆分任务、分发、汇总，并复核一般任务。
- DeepSeek Flash 承接常规执行任务。
- Codex Astra 承接高难度任务及重点复核。这里沿用讨论中的名称，实际可用模型标识待核对。

## 建议的最小流程（待确认）

1. 用户在项目目录启动 CLI，输入目标。主控先读取项目规则与文档，生成可检查的任务清单和验收条件。
2. 主控按任务复杂度分派。执行者只取得明确的项目目录、任务说明、产物路径和权限；主控保留最终决策。
3. 执行者回传完成状态、文件差异、验证命令及结果。主控检查差异与结果；高难度或争议项再交 Astra 复核。
4. 检查未通过时，主控给出具体返工意见并限制重试次数。通过后向用户报告改动、验证与剩余问题。

首版建议串行派工，任务状态至少包括待派发、执行中、待复核、需返工、已完成和失败。状态及每次派工回执应持久保存，以便 CLI 中断后恢复；送达结果不确定的任务先核对，不盲目重复执行。并行写同一工作区、自动合并与自动发布先不纳入最小范围。

## 需进一步确定

- “DeepSeek Flash”和“Codex Astra”的准确服务、模型标识及接入凭据方式。
- 执行端是 API、现有 CLI，还是二者都支持；对模型的工具调用、文件写入与命令运行开放到什么程度。
- 主控判断高难度、升级复核、失败重试和请求人工决策的规则。
- CLI 命令名称、交互形态、费用与用量上限，以及首版验收用例。

现版 `universal_rpc.py` 已连接 Codex App Server，桌面后台有任务控制、审批与持久化能力；这些只能作为设计参考，尚未构成上述多模型调度 CLI。开发前须核对新入口与现有桌面控制权、审批和工作区规则的一致性。
