# 桌面使用说明

[文档索引](README.md) · [启动、构建和维护命令](RUNBOOK.md)

## 窗口与后台

个人同步版的托盘「跨机接续」可以配对设备、查看每个仓库的状态以及打开项目。任务里的「启卷」直接用 VS Code 打开本机已有项目。尚未下载的项目由后台准备目录，准备好后打开。顶栏「任务 → 项目分组与同步…」可自建分组并设置同步频率。 [项目分组与同步](PERSONAL_SYNC.md#项目分组与同步优先级)

正式入口为根目录 `desktop_app.py`。源码运行优先选择 Qt，缺少 Qt 时回退到 Tk，再回退到 Win32；Qt 提供完整的 Codex / Claude Code 双客户端界面。Tk / Win32 是功能较少的兼容界面。

澜汐用原生 Qt 绘制整窗壁纸和两块同材质的毛玻璃。顶部居中的胶囊在 Codex、Claude Code 和「吉光片羽」间切换。左侧「案头诸事」可以搜索和选择任务，右侧「灯下对谈」保留可滚动消息与固定输入区。托盘菜单可打开「运行与额度」。

从顶部菜单栏点「测试」可打开测试窗口。R37 已连接云服务器时自动执行服务器测试，未连接时自动执行本机自检；「项目会话诊断」可选择实际项目文件夹。Windows 右下角的澜汐托盘也提供同一入口。 [验收步骤](PORTABLE_CHECK.md#运行验收)

顶部滑块可点击或拖动，按下时立即变亮，拖动时跟随指针，释放后以弹簧曲线停靠。再次切换时会从当前位置继续。系统关闭动画效果时立即切换。

鼠标碰到窗口内顶边时，菜单栏淡入，离开菜单栏后淡出。顶栏可打开「连接云服务器」「测试」和「合流」。点「合流」会安排新一轮同步，并显示项目同步结果、冲突或欠缺的大文件。当前同步还在进行时，新一轮会排在它之后。 [连接方式](CLOUD_COORDINATOR.md#在澜汐中连接云服务器) · [手动同步](PERSONAL_SYNC.md#手动同步)

源码版的左上角「澜汐」也提供系统托盘的全部命令，包括吉光片羽、运行与额度、测试、待审批请求、用户数据目录、项目母目录和退出程序。展开「跨机接续」会按当前配置显示配对及同步选项。便携构建还会显示「检查更新」。窗口菜单另有「关于澜汐」。

R35 在项目母目录有 Git 标记时仍扫描子项目。使用「本机使用」时，「案头诸事」继续读取本机 Codex 会话，未匹配到项目的会话也能按原工作目录查看。云连接模式的「合流」分别显示 GitHub 与服务器备份结果。从「跨机接续 → 下载服务器代码备份」可以保存选中来源设备的 ZIP。 [项目扫描与服务器备份](PERSONAL_SYNC.md#代码的服务器备份)

弹窗和下拉菜单沿用主界面的海蓝色系、字重及按钮层级。

## 项目介绍与会话整理

点击左栏项目名称，右栏显示项目名称和本机目录。存在本机记录时也显示 Git 仓库和分支，点击「打开文件夹」打开项目目录。双击「项目用途」或「当前进展」的文字进入编辑，Enter 保存并回到普通文字，Shift+Enter 换行，Esc 取消。空白字段显示「双击添加」。切换项目会保留草稿，退出前可保存或放弃。点击会话行回到对谈。介绍、列表顺序和栏宽保存在当前电脑。鼠标移到两栏之间会出现调宽光标和圆点，按住左键拖动即可调整。

右击会话可移动到指定项目下显示或重命名。已配对的 Codex 会话可从「删除…」打开摘要及删除确认。拖到行上缘或下缘可调整顺序，同一分组内可拖动项目。拖到另一个 Codex 会话行中央会打开浓缩转入预览。确认后，澜汐把摘要写入目标上下文，验证后再提交源会话删除。目标对谈会显示「转入的会话摘要」。转入使用两条不同的 Codex 会话，源会话需要可安全读取，目标需要空闲并由本机取得写入权。 [会话整理工单](DELIVERY_STATUS.md#左侧项目与会话整理)

「灯下对谈」自动排版 Codex 和 Claude Code 回复中的 Markdown。标题、列表、引用和表格在原来的半透明气泡内显示，行内代码和代码块使用浅蓝底与等宽字体。长代码行随窗口宽度换行，可选中内容复制。点按网页链接会打开默认浏览器，外部图片显示描述文字。

R43 的 Codex 对话分别显示最近 50 条正文消息和最近 50 条执行札记，并按发送时间排列。读回原生会话记录时，会按同一轮内的消息内容合并重复来源，并保留不同的补充输入。

R44 在消息等待重连时显示发送状态。能确认尚未写入 Codex 连接的指令在恢复后由后台发送，沿用原操作编号；暂停或移出任务会取消仍在等待的指令。已经写入但缺少确认时显示结果未确认，可先在会话里核对是否收到。

R46 的人工发送会立即唤醒后台。额度和会话列表在独立线程中读取。暂时读不到会话列表时保留上一次成功结果。

发送时先显示本地气泡，标明待发送、等待重连、已送达、发送失败或送达未确认。可从失败或未确认的气泡取回原文。输入框已有新草稿时，原文会复制到剪贴板。后台核对到 Codex 或 Claude 的原生记录后会合并对应气泡。

### 压缩并删除 Codex 会话

R46 可在已配对的澜汐中右击一条已结束的 Codex 会话，选择「压缩并删除会话…」。Codex 根据旧上下文生成简短 Markdown，可在预览框编辑。点击「保存摘要并删除…」并确认后，澜汐把摘要保存到用户数据目录的 `会话摘要/<会话 ID>.md`，核对内容后才向服务器提交删除。删除记录随个人同步送达配对电脑，离线设备恢复连接后处理。顶部「任务 → 会话摘要与删除进度」显示摘要路径和已回执的设备。

设备需更新到支持此功能的版本。若 Codex 或 VS Code 仍持有原会话，先退出原会话。原生删除会级联子会话，因此该入口只处理没有独立子会话的对话。服务器清理澜汐同步存储中可归属该会话的原始记录和独占分块。 [跨机删除工单](DELIVERY_STATUS.md#session-retirement)

澜汐接入的 Codex 会话会流式显示回复。命令放进浅蓝灰色的「执行札记」气泡，等宽文字显示命令与输出，同一个气泡随运行状态更新。结束时显示耗时或失败退出码。停留在对话底部会跟随最新输出，上滑后可继续阅读旧消息。气泡保留末尾最多 6,000 字符、30 行输出，超出时标明省略。

点击左侧任务即可接入，接入成功后会断开同一客户端中的其他任务。接入失败时保留原有连接。断开会停止澜汐对旧任务的控制和自动推进，其已启动的轮次继续执行。

鼠标移入对谈标题区或键盘聚焦操作按钮，工具栏就会浮现。接入、暂停、继续依次叫「执舟」「暂泊」「续航」，自动推进用「扬帆」和「收帆」，移出和打开 VS Code 项目用「移离案头」和「启卷」。把鼠标停在按钮上可查看动作含义。双击对谈标题或聚焦后按 F2 就地改名，Enter 保存，Esc 取消。Codex 标题先在澜汐更新，取得写入权后同步原生标题。点击「标题冲突」可选择保留原生名或再次提交。对谈输入区用 Enter 或 Ctrl+Enter 发送，Shift+Enter 换行。

发送后可以立即继续输入或切换会话。气泡显示「待发送」「等待重连」「已送达」「发送失败」或「送达未确认」。确认未写入的 Codex 指令会在重连后继续发送，送达未确认的指令需要自行核对。用「取回原文」将指令带回输入框，已有草稿时原文会复制到剪贴板。

收到可处理的审批请求时会自动打开桌面审批窗。 [审批操作](#审批窗口)

桌面程序自己启动后台工作线程。关闭开发终端或 Codex 窗口不会关闭已独立运行的 EXE；Qt 关闭窗口会缩到系统托盘，选择「退出程序」才会停止后台。0.7.3 修复“先隐藏到托盘、再退出”后 Qt 主循环残留的问题：退出显式结束主循环，后台停止、定时器和托盘清理仅执行一次，单实例锁保留到主循环结束后再释放。程序通过 Windows 单实例机制防止重复打开桌面实例。

R42 关闭主窗口缩到托盘时，澜汐自动交还本机持有的任务控制权。等待当前轮次、审批和同步时，可以右键托盘图标查看状态。托盘期间继续同步并接收审批和完成提醒。恢复主窗口时，正在执行的交还步骤先收尾，尚未执行的交还停止。已交还的会话可按需重新「执舟」。Windows 任务栏的普通最小化保留当前会话控制权。 [任务控制](PROJECT_CONTROL.md#个人版项目占用)

`monitor.py` 是桌面进程内部的后台编排模块；应用统一从桌面入口启动。

## 审批窗口

「待你定夺」汇总澜汐接入或共享 App Server 上报的 Codex 审批、本机 Claude Code 审批，以及同工作区设备共享的 Codex 请求。R40 独立检查审批队列，有新请求时自动显示并尝试置前窗口，主窗口缩到托盘也会检查。左栏显示请求、任务和执行设备，右栏显示可核对的工作目录与命令或权限。

- 勾选请求后点「同意所选」。点「全部同意」会提交当前窗口中所有可同意的请求。缺少可核对详情或已在等待回执的请求会跳过。
- 左栏点选一行查看详情后，可点「拒绝当前项」。关闭窗口后，可从对话区、顶栏「任务 → 待你定夺」或托盘回看待审批请求和近期结果。
- 跨机提交后，状态先显示「等待回执」，来源设备处理后逐项显示结果。送达结果不确定时显示「结果未确认」。独立 Codex App Server 的审批由原客户端处理。Codex 完成提醒由后台读取已完成轮次后发送。
- 从 R36 起，共享连接在本机或跨机同意前都会核对项目控制权。旧任务已交还或控制权已转移时，审批返回「控制权已变更」。 [工单与复测状态](DELIVERY_STATUS.md#r35-review)

在澜汐托盘选择「VS Code 审批提醒…」查看本机配置状态，点「启用或更新」配置提醒。重启 VS Code，在 Codex 输入框旁的 **Review hooks** 审查并信任「澜汐审批提醒」。也可在同一 Windows 账号的终端打开 Codex，用 `/hooks` 完成审查。使用自定义 `CODEX_HOME` 时，澜汐、终端和扩展需使用同一配置目录。澜汐运行时，收到支持的审批事件会置顶显示项目和工具名。实际确认在发起请求的 Codex 窗口操作。同一菜单提供「停用」。 [Codex Hook 官方说明](https://learn.chatgpt.com/docs/hooks#permissionrequest)

澜汐完全退出时，由 Windows 弹出「Codex 等待审批」。同一条跨机审批在短暂断线重连后仍可从托盘「查看待审批请求」打开，已自动显示过的请求不会再次弹出。

R50 完成提醒默认在运行会话的电脑显示。想在当前电脑接收配对电脑上新完成的轮次时，在托盘勾选「接收其他电脑的完成提醒」。这个选项保存在当前电脑。

已完成 R35 包内界面的隔离 Qt 验证和双设备模拟联调。R36 包内的最终界面改动已通过独立复测，实体双机及真实客户端审批仍待现场验证。 [R35-03](DELIVERY_STATUS.md#r35-03) · [后端接口及支持范围](ARCHITECTURE.md#全局-codex-监控与审批队列)

## EXE 与数据

在 Windows 上解压运行当前便携包。已配对设备可用托盘「检查更新」安装新版。托盘还可打开用户数据目录或重设项目母目录。新发现的项目会进入 Codex 案头。默认源码构建名为 `release/Lanxi.exe`。 [安装、升级与验收](PORTABLE_CHECK.md) · [历史构建记录](archive/IMPLEMENTATION_LOG.md)

首页从 25 联唐诗里每小时轮换一句，并同步显示作者与篇名。重开窗口沿用当前小时的诗句，电脑唤醒后直接显示当时的一句。诗句可离线轮换，副标题沿用开发方案封面原文。选诗参考 [Wscats/poetry-skills](https://github.com/Wscats/poetry-skills) 使用的 [chinese-poetry《唐诗三百首》](https://github.com/chinese-poetry/chinese-poetry/blob/master/全唐诗/唐诗三百首.json)，并参考 [常建《题破山寺后禅院》](https://zh.wikisource.org/wiki/破山寺後禪院) 与 [钱起《省试湘灵鼓瑟》](https://ctext.org/text.pl?if=gb&node=153790) 的原文。

上一版仍在运行时，先从托盘退出再打开新版。R21 和后续同一数据版本的桌面包共用当前 Windows 用户的数据目录。单文件内含 Python、Qt 和壁纸。运行任务需本机已安装并登录对应的 Codex / Claude CLI。

澜汐启动时会读取 Windows「图片」下的 `澜汐/macOS`，包括各版本子目录。横版和方形 JPG、PNG 原图用于全窗背景，窗口取画面中央等比裁切。默认每 30 分钟换一张。图库里有 `10.9 Mavericks` 时从这张海浪开始，其余按路径排序。原图可从每张壁纸详情页的下载按钮取得。[AppleWalls macOS 合集](https://applewalls.com/zh/macos-wallpapers)

源码和 EXE 共用当前用户的 Windows「图片」图库。新电脑上可复制整个 `澜汐/macOS` 文件夹。没有可用的本机或自选图片时，会轮换未移出的内置壁纸。用 `desktopWallpaperMinutes` 调整间隔，设为 0 后停止自动轮换，启动优先显示可用的 Mavericks。系统关闭动画效果时直接切换。 [内置壁纸来源](https://512pixels.net/projects/default-mac-wallpapers-in-5k/)

### 壁纸管理

在 R35 主窗口里，把鼠标移到顶边，打开「设置 → 壁纸管理」。打开时选中当前壁纸。左侧可浏览本机图库、自选图片和内置壁纸，右侧显示选中图片的预览、原图分辨率、来源及路径。内置壁纸显示随包文件名。浏览其他图片后，可点「查看当前壁纸」回到正在显示的那张。

- 「添加图片」可多选本地 JPG、JPEG、PNG。澜汐保存副本并自动区分同名文件。自选图片可为竖版，整窗显示时仍使用居中裁切。
- 「立即显示」马上切换窗口壁纸，自动轮换开启时从此刻重新计时。固定模式下，本次运行会停在手动选中的图。
- 「移出轮换」保留原文件与导入的副本。移出当前图后会换成下一张可用图片。都移出后显示纯色背景。列表中标为「已移出」的图可以恢复。

自选图片和移出记录保存在当前实例的数据目录，关闭窗口或重启后仍保留。该入口已通过 R35 包内界面的隔离验证。 [配置和存储位置](CONFIGURATION.md)

R21 起，便携 EXE 将 `local-config.json`、任务数据库、回复记录和草稿保存在 `%LOCALAPPDATA%\Lanxi\data`。源码运行继续使用项目根目录。 [配置说明](CONFIGURATION.md)

正式使用前应检查源码与 EXE 使用的数据根目录。构建预览版时可指定不同文件名。完整步骤见 [运行与维护](RUNBOOK.md)。

## 任务操作

在「案头诸事」选中同一条 Codex 会话后，「灯下对谈」会补显示 VS Code 终端里已落盘的消息。两端使用同一个本机 Codex 数据目录。终端占用期间可查看历史，释放写入权后可从澜汐继续该会话。 [桌面与 VS Code 终端续接](MULTI_CLIENT.md#codex-桌面与-vs-code-终端续接)

右键点击「案头诸事」中的 Codex 会话，选「查看会话 ID」，再点「复制 ID」即可在终端恢复原线程。跨机接入同一 GitHub 项目前，先等另一设备完成当前轮次并交还任务。 [终端续接步骤](PORTABLE_CHECK.md#终端和澜汐接着同一段对话) · [项目占用与交还](PROJECT_CONTROL.md#个人版项目占用)

独立终端运行期间，澜汐读取 Codex 已保存的命令完成记录。实时增量来自澜汐连接的 App Server，取决于当前 CLI 提供的事件。正在显示的过程输出仅在本机桌面使用，澜汐不另行写入回复日志或推送到通知和 Web。

在已执舟的 Codex 会话里，在空输入框键入 `/`，上下键或鼠标选择 `/model` 和 `/permissions`。回车打开选项，Esc 收起菜单。模型和权限档位来自当前 Codex，受限制的档位显示为不可选。

设置只作用于所选会话的后续轮次。权限档位沿用当前审批策略。重连后以 Codex 返回的会话设置为准。功能依赖本机 CLI 提供的 App Server 会话设置接口。[Codex 斜杠命令](https://learn.chatgpt.com/docs/developer-commands?surface=cli#slash-commands)

案头按项目目录分组。同一个项目开多个终端时，各段会话显示在同一个可折叠组里。在 Git 项目的子目录启动终端也会归到仓库根目录。同名项目用父路径区分，搜索支持项目名、会话名和路径。

组内优先用本机已保存的会话标题。Codex 也可用本地记录中第一条有内容的用户消息作简短标题，手动更改的名称优先。左侧「待执舟」「执舟中」「已执舟」对应右侧「执舟」，「已暂泊 · 待续航」对应「暂泊」与「续航」。

手动设置的任务名称保存在每个客户端独立的本机 SQLite 控制库中。客户端切换会保留各自的任务选择和输入草稿，另一端后台继续监控。

重新接入保留已保存的手动暂停。如果 Codex 已在后台运行，但本地仍标记暂停，状态会明确显示“本地已暂停 · 后台运行中”，有控制权时“继续任务”保持可用。此时点击继续只解除本地暂停，恢复对当前轮次的消息发送，不补发继续提示词，也不新建轮次；原有自动推进开关保持不变。观察模式仍禁止发送与继续。Claude 的暂停确认规则保持不变，须等中断完成后才能继续。

Claude 运行中发送指令通过 CLI stream-json 的 `priority: now` 输入插入当前会话；不启动第二个进程，也不要求等待整轮自然结束。暂停会优先发送 interrupt 并取消等待队列，避免插队指令在暂停后又开始运行。只有与本次中断意图、轮次匹配的 `Interrupted` 或特定 `[ede_diagnostic]` 回执才归为正常中断；其他执行错误仍会提醒。进程由本监控启动并持有才可控制；原窗口占用时只读关注。

Codex 开启自动推进的任务在额度耗尽后进入“等待额度刷新”，不会反复发送继续指令。程序持久保存受限窗口的刷新时间；短周期和长周期均受限时等待较晚的时间。到点重新读取官方额度，只有 `ordinaryUsageAllowed=true` 且限制已解除，才自动恢复原来的 `usageLimited` 目标并继续一次。不修改目标内容、用量或预算；已完成、目标暂停、预算受限、无控制权或待审批的任务不自动恢复。接口未知或未返回刷新时间时会明确显示并定期重新查询，不靠时间推断恢复。手动“暂停任务”、关闭自动推进或移出会取消自动恢复，重启后仍尊重这些选择。

主界面围绕当前任务与下一步操作展示。后台返回失败或结果不确定时弹窗提醒；消息发送失败且输入框为空时恢复原草稿，已有新草稿不会被覆盖。点按钮表示已提交，仍需等最终状态确认。送达不确定时不自动重发。

Claude 的“自动推进”由本监控定时器实现：默认关闭，手动开启后先等待一小时，随后只对本监控持有、实时空闲、没有待审批或执行错误的会话发送一次继续指令。周期、发送预留和结果写入本地控制库；暂停或关闭后不再发送，送达不确定时关闭自动推进，不能盲目重试。任务完成后应关闭此开关。Codex 保留自己的 goal 和调度检查。

启动时只加载旧操作历史，不重弹过去的失败。新操作失败仍会提醒，历史记录继续保存在本机。

## 吉光片羽

从顶部第三栏或系统托盘进入「吉光片羽」。R35 左栏顶部有「拾得片羽」「待理诸事」「每日记录」三段圆角矩形滑块。点选或拖动小滑块都能切换，Tab 和空格也可操作。系统关闭动画时直接切换。

切到「拾得片羽」或「待理诸事」，点右栏标题旁的「＋」新建。正文首行出现在左侧，写一句也能自动保存，提示为「已收于此」。旧记录的题名和正文都可以在同一个编辑区读回。

点待办左侧方框打勾，再点一次即可取消。勾过的条目留在原位，字色淡成灰蓝。选中条目后也可按空格切换。随记可在右栏「⋯」收入旧笺、翻看归档和恢复。

切到「每日记录」后，左侧按 `YYYY-MM-DD` 从新到旧列出有内容的日期。每个日期只有一行，右栏合看当天的随记、待办和完成状态。当天保存的内容也可即时查看。按本机日期跨天后，之前的随记和已完成待办从日常列表归入日期记录。未完成待办继续留在「待理诸事」。跨天续写或办结时，前一天的原文和完成状态仍可查阅。已有笔记会按原保存时间归入对应日期。

笔记、待办和每日记录的历史内容保存在实例数据目录的 `lanxi-notebook.sqlite3`。已配对设备从 R25 起逐条同步随记、待办、完成状态、归档和手动分组。使用支持每日记录的版本时，也会同步跨天保留的历史内容。两边同时改动同一正文时，可在「吉光片羽」查看冲突副本。模型自动分组由各机本地生成。 [个人同步说明](PERSONAL_SYNC.md)

## 大模型归组

在顶边菜单的「设置 → 大模型 API…」中填写 OpenAI 兼容接口的基础地址和模型名。由接口决定是否填写 API Key。外部地址使用 HTTPS，本机回环地址可使用 HTTP。留空密钥会沿用当前地址已保存的密钥，地址更换时可填写新密钥或勾选移除原密钥。清空地址和模型可暂停归组。

保存设置后，已载入的案头会话标题和项目文件夹名、打开后的随记与待办标题和正文片段，会按各自类别送到该接口进行后台归组。普通任务仍用原项目目录接入及执行。把左栏随记或待办拖到目标组名上即可手动换组，之后以手动归组为准。勾选完成仍只更新状态。

密钥由 Windows DPAPI 绑定当前用户保护。设置和分组记录保存在实例数据目录的 `local-model-api.json` 与 `lanxi-groups.sqlite3`。

## 登录启动与验收

登录时启动本机开发版可指定 `scripts/install-startup.ps1 -ExecutableName Lanxi.exe`。省略文件名时优先使用 `release/Lanxi.exe`，其次兼容旧桌面 EXE，最后使用源码方式启动。 [登录启动说明](RUNBOOK.md#windows-登录启动)

Qt smoke 使用虚构会话核验界面按钮和显示。真实模型收发、工具审批往返、系统通知实际展示、重新登录和故障恢复需要在本机另行验收，不能从打包成功或 smoke 通过推断。

窗口应用菜单已在 Windows、Python 3.14.7 和 PySide6 6.12.0 上完成源码验收。Qt smoke 实际点开顶栏「澜汐」、展开跨机接续并进入「运行与额度」，比对托盘菜单及配对状态变化，并模拟便携模式验证「检查更新」的触发。便携包发布与更新下载待验收。
