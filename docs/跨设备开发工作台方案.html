项目要求

公司台式机、私人笔记本和家里台式机使用同一套澜汐。一次安装、配对并登记项目后，后台负责交接。日常开发路径仍是打开 IDE、编辑、运行命令，用户无需另开工作台或点击同步。

代码和会话一起到达

三端保留代码副本。已保存到磁盘的未提交修改、暂存状态、允许同步的新文件和最近可恢复的 Codex 轮次必须相互对应；绝对路径按设备映射。

人拥有最高优先级

任一设备用 VS Code 或 PyCharm 打开项目，澜汐释放该项目的自动控制。最后一个 IDE 关闭、人工 CLI 释放后，后台按原策略接回。

算力和大文件按需使用

普通开发就近执行，GPU 任务或受本机性能限制的可迁移步骤自动调度到家里。大对象默认一份持久主副本，工作缓存按需生成，重要数据另存冷备。

夜间可独立推进

项目按长期、短期或探索性管理。夜间在项目沙箱和预算内自动处理符合规则的操作审批，iPhone 可暂停、看结果和处理例外。

每天自动生成一份跨项目工作报告。Codex 对话、决策和技术探索按项目归档，供日后查阅和继续开发。新功能通过有版本的接口接入。

个人版云协调服务。 两台电脑各自通过 HTTPS 配对，使用独立设备身份接入同一个个人空间。无域名部署支持带 IP 地址的服务器证书，旧设备还可经 SSH 隧道访问回环接口。服务协调个人记录、项目占用、发布清单及大文件临时交接。部署、配对与验收

升级保留用户工作状态

此项为桌面交付原则。程序和本机用户数据分开存放。换安装位置或增加新功能后，新版继续读取原来的配置、配对、项目索引、对话、随记和待办。已存在的入口和默认行为延续。发布前使用旧版产生的真实结构数据验证一次升级，并确认升级后新增的数据能被下一次安装读取。

迁移以原数据为准，保留旧版文件。遇到多个可能的旧目录，由用户确认使用哪一份。项目代码保存在各自的项目目录，项目记忆使用约定的相对路径，Codex 原生会话沿用原有会话 ID。本机项目位置和绝对目录映射按设备保存，跨机时以共同的项目身份和会话 ID 接续。

已发布于 R30。 选择「全新开始」后直接设置本机项目母目录。第一台电脑可直接点「开始使用」，立即在本机发现项目。加入跨机同步的设备可在同一窗口填写一次性配对码。配对码提供 HTTPS 协调地址，私人服务器配对码还带服务器证书。配对完成后，凭据保存在当前 Windows 用户下，托盘显示连接与重试状态。已配对设备可从「跨机接续」邀请另一台电脑。

VS Code 和 PyCharm 的项目可以集中扫描它们共同的上级目录。不同设备可为同一 GitHub 仓库保留各自的现有目录。目录示例

每台设备只选自己的项目母目录。跨机登记 GitHub 仓库标识及项目相对于母目录的路径，保留全部子目录和原名。例：台式机的 D:\工作\客户甲\项目A 对应笔记本的 C:\开发\客户甲\项目A。代码直接在这份工作区双向同步，项目记忆再按项目内相对路径落盘。已有本机登记路径继续使用，升级时保留旧工作区。

首次使用时，用户选择集中存放项目的母目录。澜汐后台识别项目和已有会话，记录当前设备的项目路径、仓库或项目标识和项目内记忆目录。在「案头诸事」生成可以启卷的项目条目，并将已有 Codex 会话归到对应项目下。会话正文按需现读，交接时使用同一个会话 ID。

用户在母目录内新建或克隆项目后，澜汐按同样的规则自动加入案头。目录可以从界面重新选择。仅发现项目时创建本地案头条目，由用户在已有会话中继续工作，或在项目目录中开启新会话。跨机读取项目记忆仍沿用个人同步协议。

终端与澜汐接着同一段对话

同一项目下可以有多个 Codex 会话。澜汐从 Codex 原生记录读取每个会话的 ID、项目目录和已保存的对话，在「案头诸事」按项目归属列出。点开会话即可在「灯下对谈」看历史。终端完成当前一轮并退出 Codex 后，澜汐使用 App Server 的 thread/resume 接入原会话，turn/start 把下一条消息写入同一段历史。在案头右键可复制 ID，回到终端时用 codex resume -C "本机项目路径" "会话 ID" 继续。Codex App Server 接口

前端设计

不同设备打开的是同一个个人工作空间。工作台默认回到最近的项目、任务或会话，并用相同的名称、信息层级和状态表达，帮助用户接上上次的工作。

  • 让当前工作先被看见。 首页优先呈现可以继续的工作和需要用户处理的事项。设备、同步、存储和算力细节收进对应页面。只有它们影响当前操作时，才在当前界面说明原因。
  • Windows 主端交付独立的原生窗口。 桌面并排展示列表和详情，iPhone 逐层进入。审批面板保留执行设备、工作目录和实际命令。交互验收覆盖键盘焦点、触控热区、减弱动态效果和 iPhone 安全区。

文案要求

澜汐的界面文案必须有诗意。 封面、欢迎语、页面引言、日报开篇和有引导作用的空状态，都要用简净、有节奏、有画面感的中文，让文字呼应当下的场景。封面正文「白日写到的那一行，暮归时仍等着你」作为语气参考。新增页面和改版都要验收文案。

首页、日报和技术探索用贴合当下情境的古诗原句。参考 poetry-skills 按主题、意象和关键词选句，核对原文、作者和篇名后再使用。首页可借江潮写跨设备接续，日报可借暮色收束一天，技术探索可用登高写视野的展开。 Wscats / poetry-skills

桌面主标题以大号粗宋体整句同排，下方紧接作者与篇名。桌面每到整点从 25 联唐诗中离线轮换，收录王湾《次北固山下》的「潮平两岸阔，风正一帆悬。」。副标题沿用本页封面原文。窗口顶部正中的玻璃滑块依次切换 Codex、Claude Code 和「吉光片羽」。任务工作区的案头列表与对谈并排。

无感换机与数据一致性

  1. 后台准备。设备代理按项目监听已保存文件，以 Git 基线、暂存版本、工作树版本和允许同步的新文件生成快照。补齐尚未推到远程的必要 Git 对象。缓存、密钥、虚拟环境和未经登记的原始大数据按排除规则处理。
  2. 确认一组可恢复数据。CLI 完成一轮且持久记录稳定时，记录项目 ID、线程 ID、轮次、工作目录映射、代码版本及所需对象哈希。中心核对对象齐备后原子发布版本；工作区随后产生的修改进入下一版。
  3. 另一台提前准备。本机后台预取最近项目，在独立目录校验，再安全更新空闲工作区。IDE 已打开或本地出现新修改时先保留本地状态。两个版本从同一基线安全合并；同一处发生冲突时保存双方内容并提示。
  4. 终端照常启动。首次登记时为受管项目配置终端启动适配。在对应目录输入 codex 时按项目选择已验证的线程 ID，交给真实 CLI 恢复；显式子命令、主动新建会话和未登记目录沿用 CLI 原语义。对话在目标机映射后的工作目录执行。
  5. 中断后恢复。网络离线时记录本地修改。中心不可达时可查看已确认进度，自动写入权等恢复连接后再核对。对执行结果不明的命令先查状态；已经运行的外部终端在原机到达安全点后才转移该线程。

关闭 IDE 或崩溃最后一个相关窗口关闭后核对其余设备、外部 CLI、待处理工具调用和实际进程。确认人工已释放后自动连接，按项目原有设置恢复。心跳中断或失联先核对，避免误抢控制权。
进入睡眠时段按用户本地时区和设定时段生效。项目已启用夜间托管、写入权有效且预算充足时，允许在项目沙箱内读写、构建和测试，并对策略覆盖的当前工具审批自动答复。

已有审批绑定原连接及请求 ID。新版本只审批仍有效的请求，记录项目、设备、时间和规则。用户在夜间打开 IDE、点击暂停或撤回托管，后台立即停止发出新的审批及调度动作。一次夜间工具审批不会替用户决定新的产品需求或扩大任务范围。

判断时机决策与动作
运行前从项目已登记的运行配置、解释器、框架探测和历史峰值取得资源需求。需要 GPU 时优先选家里可用且环境匹配的 GPU。公司机只承担已验证能跑的任务；RTX 3050 按实际显存与用户策略作为可行的本地执行端。
运行中按作业采样进度、耗时、显存压力、可用内存、换页、CPU 和磁盘等待。资源不足错误可立即触发重新选址，持续低吞吐需结合历史基线及多个采样窗口判断。高 GPU 利用率本身可能是正常工作。
决定切换比较本机剩余时间与传输、排队和家庭执行时间。中心核对家里在线、资源余量、驱动、依赖和输入版本。可断点任务保存检查点再恢复，允许重复执行的步骤从头重跑，有外部副作用或无安全边界的步骤保留现场。
结果回到终端用项目运行入口或 CLI 可调用的作业适配器提交，保持原命令的退出码、日志和取消语义。输入使用固定快照；输出按哈希回传，在原项目版本仍匹配时落盘。用户在前台发起的作业沿用前台所有权。

验证范围　先接入一个项目真实使用的 GPU 命令和一个 CPU 命令。记录源设备、路由原因、队列等待、传输耗时、执行耗时和结果一致性。家庭 GPU 型号、显存、带宽及切换阈值以设备实测为准。

任务类型与 Codex 用量

项目登记时选择默认类型，单个任务可以覆盖。以下是建议默认策略，预算数值和睡眠时间由设置保存。

类型调度与结束条件
长期项目保留跨天目标和检查点，按每日预算推进。交还给人工时保留待办，夜间仅执行已定义范围内的工作。
短期任务设完成条件、单任务预算和截止时间。完成或预算用尽即停止自动推进，记录交付物。
探索性任务在独立工作区隔离尝试，限制轮次、耗时与预算，保留结论与实验记录，由用户决定是否将成果合入主项目。

台账同时展示账号官方短、长额度窗口及刷新时间，以及按项目和线程累计的可观测 token、轮次与运行时长。每条记录按线程、轮次和事件标识去重。官方未提供的指标标为未知；项目统计用于预算控制，账号共享额度按服务端返回值展示。

到达项目预算后暂停该项目；账号额度耗尽时所有相关任务等待官方刷新。恢复前重新核对人工占用、任务目标、预算和沙箱策略。手机可查看“哪个项目用了多少、为何暂停、何时重查”。

新 Windows 电脑双击私人发行目录中的 笔记本下载/下载澜汐最新版.cmd，脚本会建立首次启动记录，完成配对，并将最新稳定版 ZIP 下载到同目录。旧脚本已配对的 R36 用户若遇到缺少 desktop-profile.json 的启动错误，用新版脚本重跑一次即可补齐记录，沿用原设备身份。新电脑安装与修复步骤

本机 release/ 根目录保留当前稳定版 ZIP 和开发版 Lanxi.exe，目前稳定版为 R46，开发版基于 R36。新候选包在独立构建目录验收。每次正式发布并核对摘要后，负责人将被替换的稳定版 ZIP 移入 release/history/，按发布日期保留最近两个不同的历史稳定版。验收记录按版本归档。保留规则与本机归档

用户将需求交给项目负责人「代码review以及发版」。各角色通过项目工单派工、回执、交付和反馈审核结果。负责人按范围向「前端开发」「后端开发」「bug修复」派工，协调接口、依赖与验收条件。开发和修复工程师在工单提交改动及自测结果。测试工程师的对话为「测试」，负责按验收条件设计和执行测试、复现缺陷、验证修复，并报告测试版本、结果和未验证项。负责人集成代码、审核送审版本，结合测试结果核验候选包并决定正式发布。项目工作约定 · 项目工单

从修改到发布

  1. 领取工单。各角色开始或继续工作时先查自己的工单。发现可以推进的工单时，回执后立即开工，进度和实际阻塞记回原单。
  2. 任务安排与权限转达。「前端开发」「bug修复」和「测试」优先执行用户的直接安排。用户未直接安排时，按项目负责人在工单中指定的任务、优先级和验收安排执行。前端、后端、缺陷修复和测试工程师需要人工授权时，在原工单说明操作、原因和请求所在会话，由项目负责人转达给用户。有审批权限的人在原会话处理系统审批，承接人回填结果。
  3. 开始修改。先写下用户遇到的问题、复现步骤和修好后的预期行为。日常小改动可直接提交到主分支；需要跨几天完成的改动用短期分支，方便随时从稳定版本修复紧急问题。换电脑前推送当前分支，接手时核对分支并拉取最新提交。
  4. 交接与审核。各角色完成工单任务后，在原工单标记「待审核」，附上待审提交或版本、结果与未验证项，并在同一工单主动提醒项目负责人「代码review以及发版」。负责人在工单回执，确认集成范围，审核代码，跟进退回问题，复核修正提交与实包。
  5. 构建候选版本。选定一次提交，用 scripts/build-portable.py 生成带版本号的 Windows 便携 ZIP，直接验收包中的程序。构建与测试命令
  6. 验收并发布。按下表验证候选包。发现问题就修复、重新构建并复测。通过后，给对应提交打版本标签，在固定下载页或 GitHub Releases 提供同一份已测包，列出版本、改动和升级步骤。源码仓库为私有时，选择用户有权访问的下载位置。
  7. 跟踪问题。先在自己的第二台电脑或少量用户设备上升级。收到反馈时记录旧版本、新版本、失败步骤和日志；若发现启动失败或数据迁移异常，暂停分发，保留旧包和升级前的数据备份，验证修复包后再恢复发布。
