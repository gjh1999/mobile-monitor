## 阶段与交付门槛

| 阶段 | 交付内容 | 通过条件 |
|---|---|---|
| P0 接口与隔离验证 | 核对三个角色的真实模型 ID、接入协议、调用用量、限额/审批事件；验证 Windows 隔离方案与现有项目控制权 | 每个适配器都有真实往返记录、能力矩阵和缺失字段说明；跨项目读写及子进程逃逸用例结果明确。无法做到命令级隔离时，确定首版命令限制 |
| P1 Rust 核心与工单库 | Rust workspace、项目注册、SQLite 迁移、目标/工单/事件、幂等键、状态投影与恢复 | 事件先落盘再动作；崩溃重启状态一致；跨项目查询/写入被拒绝；未知结果不重复执行 |
| P2 三角色适配与路由 | Codex 主控、Flash、Astra 适配器，统一事件和能力描述，派工/交流/复核流程 | 三角色通过工单完整跑通一个真实任务；消息、工具请求、回执和失败均可追溯；配置不支持的参数被明确拒绝 |
| P3 执行隔离与审批 | 项目受控文件工具、命令执行边界、项目审批规则、人工审批与控制权复核 | 跨项目路径、链接、竞态、失权、缺详情及过期规则均拒绝；自动审批只命中同项目显式规则，工单留证 |
| P4 CLI/TUI 与目标模式 | 对话、Agent 设置、工单时间线、状态面板、目标暂停/恢复/修改、可解释进度 | 用户能从终端追溯任一状态到事件；目标变化不会让旧派工继续；键盘和窄终端可操作 |
| P5 用量、日志与报告 | token 台账、项目/工单/Agent 汇总、日志检索、周期报告、审批/额度即时报告 | 实测与未知用量区分；重连不双计；报告可追溯工单并在重启后不重复投递；密钥不进入日志 |
| P6 集成与试点 | 与澜汐项目身份和控制权对齐，隔离试点、故障演练、候选包和使用说明 | 真实端到端任务、暂停/恢复、审批、额度、断网/崩溃、跨项目隔离通过；项目负责人审核后再决定发布 |

阶段顺序允许 P4 的界面原型与 P2/P3 并行设计，但正式接入真实项目必须等 P3 隔离与审批门槛通过。P0 是阻断门：若服务不提供某项能力，先调整适配器和验收范围，不假定接口可用。

## 首版最小可验收场景

1. 在测试项目建立目标，主控拆成两个子工单；Flash 完成一个，Astra 接受升级工单；所有消息、动作、验证与复核都有工单事件。
2. 用户在 TUI 查看三个 Agent 的空闲/执行/待审批/额度受限状态，打开工单能看到谁在何时提出或执行了什么，进度能对应验收项。
3. 修改一个 Agent 的模型/参数/预算，新调用采用新配置，进行中的调用保留旧快照；不支持参数显示原因。
4. 同项目规则允许的具体操作自动通过，规则外操作等待人工；撤销规则、失去项目写入权或缺少完整操作详情时不放行。
5. 项目 A 的执行者尝试读取或修改项目 B、通过目录链接跳转 B、在 B 的工单发消息，均被拒绝并留日志；任意命令执行须通过已验证的沙箱门槛。
6. 目标运行中暂停、重启和恢复，不重复已确认的工具调用。结果未知时停在待核对状态。
7. 定时报告列出工单、状态和 token；遇到审批与额度限制立即提示。额度未知或用量缺失时明确标注，不填零或猜测值。
8. 对照已发布 R51，确认 CLI 不抢占 IDE、桌面或另一台设备持有的项目写入权；试点数据不触及正式库。

## 工程任务与依赖

- **P0 前置清单：** 收集实际 CLI/服务版本与模型名称，核对调用方式、流式事件、取消、审批、用量字段和限额信号；选一套隔离试点项目及凭据。结果写入接口矩阵，不把猜测列为能力。
- **存储先行：** 定义工单事件 schema、迁移和投影，再接模型。设置、审批、用量和报告沿用稳定事件 ID 与项目 ID，避免各模块各自生成不可关联的日志。
- **执行后接 UI：** 先用非交互命令演示完整工单流和失败恢复，再接 TUI；TUI 只读投影并提交意图，不直接调用模型或工具。
- **验证从边界出发：** 单元测试覆盖状态机与用量去重；集成测试覆盖真实适配器、SQLite 崩溃恢复、路径与权限；Windows 试点验证沙箱、项目控制权、终端交互和审批回环。真实模型费用与 token 单独记录，不把模拟测试写成真实联调。
- **文档同步：** 每阶段回填主文档、`AGENT_CLI.md`、架构、计划和验证记录；新 CLI 可用后补 `RUNBOOK.md`、`CONFIGURATION.md` 与用户使用说明。若进行接口或算法实验，按项目约定记入实验文档。

## 决策点与风险

| 决策或风险 | 处理办法 |
|---|---|
| “DeepSeek Flash”“Codex Astra”是讨论名称，实际服务/模型 ID 待核对 | P0 通过真实接口记录后写入可配置的适配器；名称变化不改工单角色 |
| Windows 任意命令可能越过项目目录 | P0/P3 先验证操作系统级隔离；不达标时禁止自主命令执行，仅开放受控文件工具和人工处理路径 |
| 供应商用量字段、缓存口径和额度信号不一致 | 统一台账保留原字段与来源；缺失标未知，不跨口径硬加 |
| 现版桌面、IDE 与新 CLI 同时操作项目 | 按同一项目控制权版本复核；无法接入共享控制权时试点只用隔离项目，不进入正式工作区 |
| 自动审批放大权限 | 项目内显式规则、默认关闭的建议设置、完整详情匹配、规则版本和到期检查；每次批准留工单事件 |
| 断线或崩溃造成重复执行 | 持久预留和幂等键；不确定结果停下核对，不自动重发工具调用 |
