# 工单 A · 升级后重复提醒 · 交接说明

## 复现

在旧版导出的配置上启用已有工作区，会产生“两条订阅”：

```powershell
cd 02-接手修障
Copy-Item fixtures\upgrade.json run.json
python deskbell.py run.json lab status    # -> outdated（旧版 toast-v2 记录仍在）
python deskbell.py run.json lab enable    # 修复前：会再 append 一条 toast-v3，导致响两次
python deskbell.py run.json lab status    # 修复后 -> current，且只有一条 deskbell/lab 记录
python deskbell.py run.json lab disable
python deskbell.py run.json lab status    # -> missing
```

回归测试：`python -m unittest discover -s tests`（8 个用例全过）。

## 根因

`subscriptions.configure` 用 `wanted not in rows` / `wanted in rows` 判断，只匹配**第三版精确记录**（`renderer:"toast-v3"`）。

- 升级前已有第二版记录（`renderer:"toast-v2"`，同一 provider/workspace/topic）。`enable` 时精确匹配失败，于是又追加一条 v3 → 新旧两条同时派发，用户“响两次”。
- `disable` 时 `wanted in rows` 只匹配 v3，v2 旧记录不被删除 → “关掉再开也不总能恢复”。
- 新电脑无旧记录，从空配置开始，所以“新电脑上没遇到”。

## 改动

仅改 `subscriptions.py`：

1. 新增 `_identity(row)`：把三版字段统一到逻辑标识 `(provider, workspace, topic)`（第一版 `owner/project/event` 也归一）。第三方订阅返回 `None`，不参与匹配。
2. `status` 增加 `outdated` 档：同标识但非当前版本 → `outdated`；精确等于 `current(workspace)` → `current`；否则 `missing`。
3. `configure` 按逻辑标识操作：
   - 启用：无同标识 → 追加；已唯一且当前 → 返回 `False`（保留原字节）；有旧版/重复 → 在首个匹配位置写入当前版本并删除其余同标识行，保持相对顺序。
   - 停用：删除**所有**同标识行（含旧版），其他工作区/第三方订阅及顺序不变。

`settings.py`、`deskbell.py` 未改动（“重复执行已生效操作保留原字节”由 `configure` 返回 `False` 时不 `save` 保证）。

## 实测结果

- 升级配置 `fixtures/upgrade.json`：`enable lab` 后 deskbell/lab 由 v2 变为唯一 v3，`calendar`（第三方）与 `studio`（其他工作区）保留且顺序不变。
- 幂等：再次 `enable` 返回 `False`，文件 SHA-256 不变。
- `disable`：v2 旧记录也能停掉，`status` 回到 `missing`。
- 第一版 `owner/project/event` 记录同样被识别并迁移。
- 工作区标识大小写敏感（`lab` ≠ `Lab`）。

## 剩余风险

- 假设一个工作区只应存在一条 deskbell/task 订阅；“一个插件订阅多种事件”的其他 topic（非 `task`）不受影响、保留原样，符合预期。
- 未覆盖“同一路径配置被外部并发写入”的场景（本工具单进程单次执行，无并发锁，沿用原有 `save` 的 `tmp.replace` 原子替换）。
- 配置 JSON 里除 `subscriptions` 外的其他顶层字段（如 `theme`）原样保留，未做校验。
