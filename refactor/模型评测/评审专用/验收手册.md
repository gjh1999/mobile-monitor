# 评审者验收手册

先冻结模型交付的版本，再在单独的评审工作区运行。公开项目、候选源码、A 和 B 的项目目录、三方状态目录及取证目录分别存放。把隐藏输入放在评审机，按需送入导入接口。用[评分表](评分与结果记录.md)逐项记分。

## 操作约定

1. 按候选提交的 README 把启动、同步、暂停传输、恢复、导入、查询、强制退出和单次丢回执分别对应到实际命令。允许固定端口、状态路径等参数。记录命令和版本。同一轮不用人工改候选源码或数据库。
2. 先按[公开测试说明](../参测材料/公开测试说明.md)执行 U1～U3。每个隐藏场景另用全新的临时根目录。**场景内**重启要复用原身份、端口和状态目录。逐项确定收敛或等待 30 秒，超时保存两端状态。
3. 用文件字节 SHA-256、逻辑消息历史和服务端操作回执作为证据。Windows 可用 `Get-FileHash -Algorithm SHA256 -LiteralPath $path`。文本夹具采用 UTF-8、无 BOM 和 LF。强制退出仅对该场景启动并记录的进程操作。
4. 留存证据时，用例目录按“模型 / 首次或修复 / 用例号”组织。每个检查点保存操作、进程退出原因、时间戳、路径或线程 ID、期望、实得和日志片段。工具日志只取本次回放窗口。

### H1　远端删除与离线修改相遇

- **准备**　按 U2 第 1 步建立共同基线并记录两端原始哈希。断开 B 与服务的传输，保留 B 的进程和本地写权限。
- **动作**　在 B 的 `data/readings.txt` 末尾追加一行 `31` 并触发本地处理，确认其字节仍在磁盘。A 删除原路径并同步，取到服务器已接受删除的证据后才恢复 B 的网络。触发同步，等待冲突记录。再重启 B 并重复同步。
- **判定**　B 的修改版可从结果中的文件或冲突副本读取，SHA-256 为 `5e0bcdd059a560fb5cee284124be5d22891e6e184c3b4e0b37c9c7ca869983ed`。同一路径的远端删除和本机分叉均可辨认，重启后仍能找回修改。取证包括删除回执、修改副本路径及其哈希、冲突列表。后台提交过删除却无提示恢复原路径，也不算正确解决冲突。

### H2　回复中途断线，重放相同事件

- **准备**　使用[隐藏事件](隐藏事件.jsonl)。按原文件顺序切两份，第一份为第 1～4 行，第二份为第 3～7 行，两份都保留原来的 ID。可在评审目录执行以下 PowerShell 命令，生成文件放在取证目录。输入只在 A 导入，历史从 B 查询。

  ```powershell
  $rows = Get-Content -LiteralPath $hiddenSamplePath -Encoding utf8
  $utf8 = [Text.UTF8Encoding]::new($false)
  [IO.File]::WriteAllLines((Join-Path $evidenceDir 'part1.jsonl'), [string[]]$rows[0..3], $utf8)
  [IO.File]::WriteAllLines((Join-Path $evidenceDir 'part2.jsonl'), [string[]]$rows[2..6], $utf8)
  ```

- **动作**　导入第一份，等 B 显示未完成回复「哈」，保存历史。断开 B，在 A 导入第二份，随后恢复 B。待历史完整后再导入整个原文件，强制退出并重启 B，再导出同一线程。
- **判定**　按[预期历史](预期历史.json)逐项核对首次收敛、全量重放和重启后的结果。只比较逻辑字段，可人工将候选格式映射到表中。第 4 行重放应去重；第 5 行是另一条内容相同的事件，最终文本以两个「哈」开头。B 只有一条完成回复，工具结果仍关联 `mark-7`。
- **工具副作用**　`fixture.append_marker` 是合成调用，其历史结果已经包含在输入中。若提交支持工具派发，用其测试记录器监视该调用并在独立临时目录观察标记；增量接收、重放及重启的派发次数都应为零。若提交只有只读投影，结合历史前后输出，检查并记录导入和恢复代码入口没有通往执行器的路径。单凭没有标记文件不足以证明通过。

### H3　已提交，成功回执丢失，两端重启

1. 从空项目启动 A、B 和服务。正常连通后开启候选的**丢弃下一次文件提交成功响应并阻止立即重试**控制。在 A 写入 `notes/receipt.txt`，内容为 ASCII `sample-42` 加一个 LF，触发同步。
2. 在同一操作上取得两个证据：服务端已持久记录提交，A 正在等待回执或保留待重试记录。保存逻辑操作标识、路径版本或提交日志基线。若只做到了请求发送前断网，记“故障未命中”，不得据此判定通过。
3. 在第一次重试前强制结束 A、B 和测试服务。保留状态目录，解除丢包后先启动服务和 B，再启动 A 并放行重试。保存服务恢复后的原回执、重试记录、最终版本及 A 的待传状态。
4. B 的最终文件哈希应为 `1984ce680995c0b0e46432d070ab1307df43324309f4dd6252a0b9632939fcd2`。服务端对这次修改只承认一次逻辑提交，A 最终清除对应待传记录。已有提交通过重试或读回原回执获得确认都可接受。再重启 A 和 B，核对两端文件、操作次数及队列状态。

## 裁定与修复反馈

静默覆盖已保存的本地修改、丢失已确认的消息或因历史回放派发工具，均将本轮标为“核心未通过”，同时保留逐项分数。因缺少故障控制、无法启动或取证不足而没有完成关键检查时，标为“核心未验证”。其余结果按评分表判定。反馈仅给用例类别、前置状态、动作、可见现象和预期行为，隐藏输入及答案保留在评审端。
