# 参测任务书 · 文件与 Codex 消息同步引擎

## 复制以下提示词开始

> 请在当前工作区实现一个可离线演示的文件与 Codex 消息同步引擎。用 Rust 编写本地客户端核心，用 Go 编写协调服务。先读本任务书和《公开测试说明》，再实现、运行测试并交付源码。最终给出从干净工作区启动服务和两个客户端的一条命令、运行测试的一条命令，以及故障注入、取证和重启的具体操作。说明实际验证范围与已知限制。保留题面和样本原件。

## 工作环境与交付接口

A、B 各有独立项目目录、身份和持久状态，服务端有自己的持久状态。客户端只通过协调服务交换数据，支持单独断开 B 后继续使用 A。构建完成后的验收只需本机回环网络；输入和 Codex 事件全部来自随题文件。运行真实 Codex、接入账号、部署到公网和实现图形界面留给后续评测。

在提交物的使用说明中列出可逐条执行的命令或等效控制步骤，并写明依赖版本、端口、数据路径和退出方法。提供以下观察和操作能力，命令名称和内部协议由你选择。

| 操作 | 评审者要能做什么 |
|---|---|
| 启动与重启 | 用一条命令从空状态启动三个进程。能单独强制结束任一进程，再用同一数据目录恢复。 |
| 文件同步 | 对 A 或 B 的项目副本进行增删改和重命名，可显式触发同步。能查到本机待传、冲突及服务端已提交变更。 |
| 事件输入与查看 | 向 A 导入指定 JSONL 文件或指定行段，能在 B 查看按线程和轮次整理的完整历史，重启后可再查看。 |
| 暂停与恢复 | 控制一端离线、在线，能判断队列已处理完成，或明确报告仍有待传或待解决的冲突。 |
| 回执丢失 | 提供可重复的单次故障注入或等效代理操作。在服务端已持久提交、发起方尚未收到成功回执的位置丢掉响应，能在首次重试前暂停发起方。展示同一操作重试前后的提交次数或版本。 |
| 历史回放 | 工具调用与结果作为消息历史保存。让评审者能检查回放有无派发工具，提供可观察的调用记录或说明可核查的只读回放入口。 |

## 文件语义

在线保存后另一端应得到相同字节。同步已经收敛时可以继续从任一端修改。设备离线期间，本机已保存的更改必须可恢复。如果远端和本机都改了同一基线，要能找回双方内容；删除与修改相遇时，同时呈现删除意图和可读取的修改内容。重复传输和进程重启后，同一已确认变更只能产生一份逻辑结果。补充样本与项目的形状及事件格式一致，文件名、内容和 ID 可变。

## 消息输入约定

[公开事件](公开事件.jsonl)是本题定义的合成交换格式。每行是一条 UTF-8 JSON 对象。所有事件都有 `event_id`、`thread_id`、`turn_id`、`seq`、`type` 和 `item_id`。本版样本的序号在每个线程内从 1 连续递增；分批传入时会重放已经投递过的事件。相同事件 ID 重放时内容相同。

| type | 额外字段 | 还原规则 |
|---|---|---|
| `user.message` | `text` | 按原文展示一条用户消息。 |
| `tool.call` | `call_id`、`name`、`arguments` | 展示工具名及结构化参数。 |
| `tool.result` | `call_id`、`result` | 展示结果并按调用 ID 关联到调用。 |
| `assistant.delta` | `text` | 同一回复按事件序号拼接。两条不同事件即使文本相同，也各贡献一次。 |
| `assistant.done` | 无 | 标记该回复完成，保留此前文本。 |

同一轮次内，逻辑条目以首次出现的序号排列，接收端保留原线程、轮次、条目和调用标识。重放后仍能读取已确认历史。提交你自己的测试、运行结果和故障说明。
